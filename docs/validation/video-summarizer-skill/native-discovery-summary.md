## 一句话总结
作者分享了一套手把手方案：借助开源项目 `deep code` 把本地 AI harness（“deep sick harness”）封装到安卓，再通过 ADB 无线调试授权，把小米 14 Pro / 小米 Pad 9 变成一个“比 SIRI 更 SIRI”的语音助手，并演示了语音操作设备、插件配置与出差“救急应用”，同时重点提示了 ADB 授权带来的隐私与误操作风险。

## 章节要点
### [00:00] 开场段子与主题引出
- 作者拿自己出差照片被网友调侃“头发炸毛、像被雷击”开场，AI 回应“头发还在云端巡航”“把你拍成机场信号卡”，随后引出“今天教大家一个绝活”。
- 主题：绝大多数安卓设备都能拥有一个“比 SIRI 更 SIRI”的语音助手；示例包括用语音让 AI 把照片在画板里画成素描。

### [00:38] 适用设备与软件来源
- 演示设备：几年前的主力机小米 14 Pro（安卓 16）与新买的小米 Pad 9（安卓 17）；作者称测试均无问题，其他版本问题也不大。
- 软件：`deep code` 来自把 “deep sick harness” 封装到安卓的开源项目（工程量较大，作者向原作者致谢）；作者另做了自改开源分支，但更建议实践时使用主线仓库，自改分支仅适合有魔改能力的人。

### [01:41] 教程第一步：开发者模式与无线调试
- 在设备页狂点 OS 版本号解锁开发者模式；所有操作都在开发者模式内进行。
- 在“开发者选项”里重点打开“USB 调试”和“无线调试”；“USB 安装”可开可不开，作者不建议。
- 无线调试配对：把配对码、地址与端口交给同一局域网内的 AI agent 帮忙配对，并要求它下载 ADB 环境。授权后电脑可直接装应用、传文件、截屏读取界面按钮文字，并模拟点击滑动与键盘打字——“一双能看见屏幕的眼睛和一只操作的手”。

### [03:32] 部署 deep code 到手机
- 切换手机演示：开发者选项里打开相应开关即由 agent 整体控制；不打开也可让 agent 构建 APK 手动安装。提示词很简单（给出仓库地址 + 目标设备）。
- 执行后 agent 找到小米 14 Pro 的无线 ADB，弹出提示并授权，部署完成，得到“安卓本地运行的 harness”。

### [04:18] 作者版本的插件与小改动
- 设置 → 插件中有作者配置的插件：① 启动画面“深海微光”；② `codex` 插件（屏幕上有登录按钮，弹网页输入账号登录）；③ 语音服务（本地部署千问 3 ASR/TTS，另填 API 使用 MIO 2.5 ASR/TTS，可选语音输入与回复方案）。
- 外设：小米蓝牙遥控器约 50 元，被粉丝称为“coding 神器”，关键是“蓝牙麦克风 + 按键”组合（手柄的麦需有线、非蓝牙麦）；语音键开启、确认键发送，还可删除。

### [05:32] 权限困境与风险声明
- 可用 ChatGPT 订阅登录 codex 后启用“GPT live”，对话顺滑并可调用 codex 干活，同时 ADB 工具可操作设备；作者感觉比 SIRI 强太多，缺点是有点慢。
- 关键限制：harness 当时还不具备操作设备的权限，需特殊操作赋予 ADB 权限。作者强调一步到位前先声明风险：ADB 权限极大，若 agent 能力差或无视觉，可能看不懂屏幕、误判界面，做出意外操作（如在错误 App 里发消息、改错设置、误删有权限的文件）。

### [07:22] 风险边界与无线配对配置
- 风险边界：这些操作受安卓自身权限约束，不会真把系统搞坏，但一次误操作也够麻烦；云端 API 场景下，涉及隐私和资金的界面别让它独自操作。前提是主动配对授权，只有配对过的客户端能连；关闭无线调试或删除配对即可立即断连。
- 配置要点：“无线配对码”界面必须全程保持打开（码只能用一次）。支持小窗模式时可让 agent 用“ADB 无线配对，端口 541800、本机设备 32981”自行完成；无小窗模式则让电脑端 agent 控制后台的 `deep code` 完成配对，前台保持画面。

### [08:33] 控制设备的原理与画画示例
- 原理是“看 → 想 → 动手 → 再检查”的循环：AI 先通过 ADB 截屏或读取界面按钮文字判断位置与下一步，再执行点击/滑动/输入，做完后复查是否成功。
- 画画示例：用 “informative drawings 模型”把照片变线稿，再转成触控路径，配合模拟笔压和灰度表现笔触粗细深浅；看起来是 AI 在画，实际是程序在画。其他应用同理——把问题转成一组屏幕操作并深度封装专门 skill，可实现类似“豆包手机”的效果。作者坦言暂未发现 AI 操作手机特别有用的场景，但平板上不一样。

### [09:16] 出差实战与“救急应用”
- 平板上有了 harness 后相当于一台强力电脑。作者出差不带电脑只用平板，踩坑：灰片 LUT 都在旧电脑里、iPhone 素材上传平板不便。
- 于是让 harness 开发“救急应用”——可能只用一次但会救命的极小刚需功能。作者开发的 App 会开启服务器，扫码上传素材，并把上传的灰片直接套一个 LUT，平板基本可替代笔记本角色。

### [10:28] 观点收尾与展望
- 若特别需要电脑，可另带迷你主机、用平板当屏幕（该 Pad 支持 DP）。作者认为安卓生态比 iOS 好玩太多，这种自由性在 AI agent 时代会产生更多玩法。
- 他主张 ADB 其实就应该是 agent 的 harness，甚至应在其上开发更高效的 CLI 供 agent 使用；鼓励用几年前的安卓老设备也值得折腾。结尾感谢 `deep code` 原作者仓库，欢迎大家实践、评论区互助。

## 关键结论
- 通过“开源项目封装本地 harness + ADB 无线调试授权”，普通安卓手机/平板（无需 Root）即可获得语音助手与设备操控能力。
- 授权链条是安全边界：仅配对过的客户端可连接，关闭无线调试或删除配对即可立即断开；但 ADB 权限极大，需评估 agent 能力与视觉能力，隐私/资金界面不要让它独自操作。
- 部署与无线配对是教程中最有技巧、最易卡住的两步；耳机/遥控器等外设（蓝牙麦 + 按键）能提升语音交互效率。
- 作者判断真实价值在平板而非手机：平板可当“强力电脑”使用，并通过“救急应用”解决出差中的具体刚需（如扫码上传素材并自动套 LUT）。
