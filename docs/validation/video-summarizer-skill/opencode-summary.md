## 一句话总结
本视频是一期“手把手教程”，讲如何用把 DeepSeek harness 封装到安卓的开源项目（博主称 deep code / deep sick harness），配合无线 ADB 调试，把小米 14 Pro、小米 Pad 等安卓设备变成一个比 SIRI 更强的语音助手，并说明让本地 agent 获得 ADB 控制权限的配置技巧、原理（看—想—动—再检查循环）与隐私/误操作风险。

## 章节要点
### [00:00] 开场与主题：比 SIRI 更 SIRI 的安卓语音助手
- 用“出差自拍被网友吐槽头发炸毛、怀疑被雷击”的对话开场，AI 调侃他刚下飞机、表情淡定“稳住控场”，并把他拍成“机场信号卡”。
- 让 AI 帮他画一幅画、保留“头发的气势”，引出 AI 对话与看图作画的场景。

### [00:38] 能做什么与演示设备
- 核心主张：绝大多数安卓设备都能拥有比 SIRI 更 SIRI 的语音助手；演示机为几年前的小米 14 Pro 与小米平板。
- 举例：给“女神”拍照后，可语音让 AI 在画板里画出照片中人物的素描并交给她；博主称背后有强大的 harness（专名不确定）并“接入 GBT6”（疑似 GPT，转录疑似有误）。

### [01:23] 软件来源与分支建议
- 上期已讲如何把 harness 装进平板当本地环境替你开发安卓应用/小游戏，本期是答应的手把手教程，建议关注收藏。
- 演示设备：小米 14 Pro + 新买的小米 Pad 9，分别为安卓 16、17，测试没问题；软件来自一个把 “deep seek harness” 封装到安卓的开源项目，工程量较大。
- 博主在原作者仓库基础上改造并开源，但建议实践用主线仓库，因为自己的分支不会频繁更新、更适合有能力魔改的人。

### [02:07] 开启开发者模式与无线调试
- 打开开发者模式：未开启时在设备“OS 版本”处连点几下，会提示已解锁；所有操作都在开发者模式里做。
- 在“开发者选项”中重点打开 USB 调试与无线调试；USB 安装可有可无，需要让 agent 帮装应用才打开，作者不建议。
- 无线调试：打开“输入配对码”，把配对码、地址、端口交给同一局域网内的 agent 去配对，并明确告诉它“我需要一个 ADB 环境，帮我下载”。

### [03:05] ADB 授权后的“眼睛和手”
- 设备授权后，电脑可直接给手机装应用、传文件、截屏、读取界面每个按钮和文字，还能模拟手指点击滑动、模拟键盘打字。
- 相当于给电脑“一双能看见屏幕的眼睛和一只能操作的手”；他调试时大多通过电脑操作，随后切换到手机做部署演示。

### [03:32] 在手机上部署 deep code
- 开发者选项里的开关可让整个 agent 来控制，过程中会弹提示；不打开也行，就让 AI 构建 APK 再手动装。
- 提示词很简单：给出仓库地址，让它构建到小米 14 Pro；AI 找到无线 ADB 后弹提示，点击同意即全部部署完成。
- 至此有了一个在安卓本地运行的 harness（博主称 “Depc harness”，疑似 DeepSeek harness）。

### [04:18] 插件、语音服务与小米蓝牙遥控器
- 打开“设置—插件”查看他配置的插件：插件一为启动画面“深海微光”；插件二“codex”，屏幕触控位置有登录按钮并弹出网页，输入自己账号即可。
- 语音服务：本地部署 千问3 ASR、千问3 TTS，另配置了 API（“MIO 的 2.5 ASR/TDS”，专名不确定），可在此选择语音输入与语音回复用哪一个。
- 粉丝推荐的小米蓝牙遥控器约 50 元，是蓝牙麦克风+按键组合，被称“web coding 神器”，优于必须有线麦的手柄；可操作平板，语音键开启、确认键发送、还可删除。
- 若有 ChatGPT 订阅，可在 codex 登录并启用 “GPT Live”，对话丝滑且能调用 codex 干活。

### [05:32] 让本地 harness 获得 ADB 权限：原理与风险
- 还有 ADB 工具可操作设备，作者感觉这比 SIRI 强太多，缺点是慢；但默认 harness 不具备操作设备权限，需特殊操作获得 ADB 权限。
- 原理：之前通过无线调试让电脑上的 agent 用 ADB 操作设备；现在设备上已有整套本地 harness，要让本地环境里的 agent 通过本机地址（他形象地说“阳股和重股”，含义不明）操作自己。
- 风险声明：ADB 权限极大。若 agent 能力差或无视觉，可能看不懂屏幕、误判界面、在错误 app 发消息、改错设置或误删文件。
- 它能装/卸载应用、调部分系统权限，但受安卓本身权限约束，不会真把系统搞坏，仍需评估；云端 API 要格外小心隐私与资金界面。
- 不必太紧张：前提是主动配对授权、能连上设备；不想让它动就关无线调试或在配对列表删除，连接立刻断开。

### [07:22] 无线配对配置与小窗技巧
- 保持“无线配对码”界面打开（关闭后就没了，且码只能用一次）。
- 支持小窗模式时，直接告诉 AI“用 ADB 无线配对，541800 端口，32981 本机设备”（端口/数字不确定），让它去连接。
- 连上后该设备是 “deep code” 里的一个内部单元/环境设备；若没有小窗模式，就让电脑上的 agent 控制，前台保持配对码画面、让 deep code 在后台配对。

### [08:33] 控制设备的循环与“AI 画画”
- 控制设备原理是“看—想—动—再检查”的循环：AI 先通过 ADB 截屏或读取界面按钮文字，判断当前在哪、下一步做什么，再点击/滑动/输入，之后复查是否成功。
- 画画用 “informative drawings” 模型把照片转线稿，再转成触控路径，配合模拟笔压与灰度表现笔触粗细深浅；看起来是 AI 在画，实际是程序在画。
- 其他应用同理：把问题转换成一组屏幕操作并深度封装专门 skill，就能实现类似“豆包手机”的效果；他坦言还没发现 AI 操作手机特别有用的场景，但平板不一样。

### [09:34] 出差实战与“救急应用”
- 平板有了 harness 就相当于一台强力电脑；上次出差只带平板，踩坑：拍的灰片 LUT 都在旧电脑里、iPhone 素材上传平板很不方便。
- 于是让 harness 开发“救急应用”——可能只用一次但会救命的应用，可由平板帮你开发，哪怕只是极小却特别刚需的功能。
- 他开发了一个 app：开启服务器扫码直接上传素材，并把上传的灰片自动附一个 LUT 到素材里，基本可代替笔记本。

### [10:28] 生态感受与结尾
- 若特别需要电脑，可带一个迷你主机、用平板当它的屏幕（Pad 支持 “DP 音”，专名不确定）。
- 感受：安卓生态相对 iOS 好玩太多，这种自由性在 agent 时代会产生更多玩法；认为 ADB 其实应该是 agent 的 harness，甚至应在 ADB 上加一个更高效的 CLI 给 agent 用。
- 鼓励折腾，哪怕设备是几年前的老设备；欢迎实践、支持原作者仓库，遇到难题可发评论区互助，结束。

## 关键结论
- 只要安卓设备能开开发者模式、USB/无线调试并完成 ADB 配对，就可以把本地 harness + 语音服务组合成比 SIRI 更强的语音助手。
- 让本地 agent 真正操作设备的关键，是让它通过本机地址配合 ADB 获得权限，难点在于无线配对码一次性、需要在配对界面配合（小窗模式或电脑端 agent 辅助）。
- ADB 权限极大，是主要风险：需评估 agent 能力、保护隐私与资金界面，并可随时关无线调试或移除配对客户端来断开。
- 控制设备的通用思路是“把问题转成屏幕操作 + 封装 skill”，配合“看想动查”循环；平板（而非手机）在他看来是更有价值的落地场景。
