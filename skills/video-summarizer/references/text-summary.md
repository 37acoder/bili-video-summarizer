# 仅文字总结的交付

仅在用户选择仅文字时读取。依据为字幕或自动转录，标明识别来源与疑点；不获取视频画面、不加载图文模板或样式。先读 [共用行文](editorial-writing.md)，只加载所选类别的轻量行文配置。

## 1. 按用途组织正文

默认写成文章，用导语引出主题，随后分章叙述。按共用行文与所选配置保留原片的例子、推理和语气，新增评论单独标记；纯音频同样按内容选型。

用户要速览、要点清单或复习提纲时，按用途缩短，保留必要的例子和限定。实录先整理议题和发言，把明确结论、分歧、未决问题和实际待办分开；评论按共用行文处理。

## 2. Markdown 写作骨架

按实际内容替换占位符、拟定小标题，增减章节与可选段落；交付前删净模板提示。

```markdown
# <逐字使用视频原标题>
来源：<视频链接及分P，或用户提供的转录文件>
依据：字幕文本；<完整/部分覆盖；转录质量说明>

<导语：从原片的问题、故事或冲突出发，带出主题与关键落点>

## [mm:ss] <这一段实际讲了什么>
<自然段落：问题或动机怎样出现，作者怎样展开；保留有作用的例子>

<继续叙述过程、追问或推导，解释它怎样支撑判断；数字、条件和归属明确>

> **<所选类别的评论标签>｜AI观点 · 非原片内容**
>
> <可选：按共用行文展开独立分析，给出有理由的判断及成立条件；可分多个引用段落>

## [mm:ss] <下一处内容转折>
<承接上一章，保留原片的新例子、分歧或后续更正>

## <原片最后落到哪里；标题随内容调整>
<自然收束原片的结论、限制或开放问题。只有确有帮助时另列复习点、步骤或行动项>

## 不确定与缺口
<仅在存在时列出，不确定专名、缺失块和字幕无法支持的结论>
```

章节跟着内容走，时间用于回看。重排内容后核对每章最早来源。原片结论与AI评论分别收束；已说清的内容无需再摘抄成“关键结论”。没有评论或缺口时删去相应块，成稿按共用行文通读并核对来源。

## 3. 时间与交付核验

章节标题时间取本章最早要点的首个来源item的 `s`，向下取整转换成mm:ss或hh:mm:ss，来源索引、秒数与短引文保存在chapters.json。写作后读 [文字证据与Map-Reduce](summarization.md) 的逐章核验规则，检查内容支持并运行核验命令。没有时间戳时省略标题中的时间；部分项无时间时，只标有依据的章节。默认按内容转折安排1–12章，可参考约每两分钟一章，再按关键内容调整；完整总结覆盖全部文字，片长只采用实际媒体依据。

**完成标准**：全部文字块已覆盖；正文的例子、归属、结论和更正有据，AI观点单独标记；标题逐字匹配，章节时间核验通过，未残留模板提示。保存summary.md及chapters.json，返回可点击文件路径，简述覆盖范围与现存缺口。
