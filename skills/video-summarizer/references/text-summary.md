# 仅文字总结的交付

仅在用户选择仅文字时读取。依据为字幕或自动转录，标明识别来源与疑点；不获取视频画面、不加载图文模板或样式。先读 [共用行文](editorial-writing.md)，只加载所选类别的轻量行文配置。

## 1. 按用途组织正文

默认写一篇有导语、自然段落和内容小标题的文章，沿用图文版对原片语气、例子、推理和评论归属的处理。科技写折腾过程与代价，讲座保留概念递进，访谈留住追问与分歧；纯音频按内容类型选型。

用户指定速览、要点清单或复习提纲时，压缩成相应用途的格式，仍保留例子与限定。实录优先议题和发言过程，明确结论、分歧、未决项及真实待办；评论默认省略。正文不能靠想象画面补充“生动”。

## 2. Markdown 写作骨架

下列是可调整的骨架；替换占位符，小标题按真实内容拟定，按需增减章节与可选段落，不把模板提示原样交付。

```markdown
# <逐字使用视频原标题>
来源：<视频链接及分P，或用户提供的转录文件>
依据：字幕文本；<完整/部分覆盖；转录质量说明>

<导语：从原片的问题、故事或冲突出发，带出主题与关键落点>

## [mm:ss] <这一段实际讲了什么>
<自然段落：问题或动机怎样出现，作者怎样展开；保留有作用的例子>

<继续叙述过程、追问或推导，解释它怎样支撑判断；数字、条件和归属明确>

> **<所选类别的评论标签>｜AI观点 · 非原片内容**
>
> <可选：按共用行文展开独立分析，给出有理由的判断及成立条件；可分多个引用段落>

## [mm:ss] <下一处内容转折>
<承接上一章，保留原片的新例子、分歧或后续更正>

## <原片最后落到哪里；标题随内容调整>
<自然收束原片的结论、限制或开放问题。只有确有帮助时另列复习点、步骤或行动项>

## 不确定与缺口
<仅在存在时列出，不确定专名、缺失块和字幕无法支持的结论>
```

章节时间用于回看，不决定行文顺序；内容重排时保留每章最早来源的实际时间。原片结论与AI评论分别收束，去掉无信息的“关键结论”重复摘抄。无评论或缺口时删掉相应块。

## 3. 时间与交付核验

章节标题时间取本章最早要点的首个来源 item 的 `s`，向下取整转换成 mm:ss 或 hh:mm:ss；每章的来源索引、秒数与短引文保存在 chapters.json，按文字证据文档完成逐章核验后交付。没有时间戳时省略标题中的时间；部分项无时间则只给有依据的章节标注。默认按内容转折安排 1–12 章，可参考约每两分钟一章；实际字幕结束秒数不是精确视频时长，不要伪装为完整时长。章节须覆盖全片，可调整章节数以保留关键内容。

**完成标准**：全部文字块已覆盖；正文的例子、归属、结论和更正有据，AI观点单独标记；标题逐字匹配，章节时间核验通过，未残留模板提示。保存summary.md及chapters.json，返回可点击文件路径，简述覆盖范围与现存缺口。
