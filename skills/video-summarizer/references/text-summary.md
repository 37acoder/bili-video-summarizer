# 仅文字文章的交付

仅在用户选择仅文字时读取。依据为字幕或自动转录，不获取视频画面、不加载图文模板或样式。先读 [共用行文](editorial-writing.md)，只加载所选类别的轻量行文配置。

## 1. 按用途写作

默认写成可独立阅读的文章。先确定要回答的问题，再用原片的经历、例子、推理和修正展开。纯音频同样按内容选型。用户要速览、复习提纲、纪要或逐段复盘时按该用途组织；实录中的决定、负责人、期限只采用明确发言。

## 2. 文章骨架

章节名称和数量随实际内容调整，交付前删净占位提示。原片短原话放在正文段落中，注明说话者；引用块留给独立AI评论。

```markdown
# <逐字使用视频原标题>

<从原片的具体问题、经历或短原话进入主题>

## <这一节要回答的问题或展开的观点>

<原片的经历、例子和推理，自然展开；首次出现与观点转属时明确人物>

<保留改变理解的反问、条件、分歧或后续修正>

> **<所选类别的评论标签>｜AI观点 · 非原片内容**
>
> <可选独立分析：从具体主张出发，给出理由、判断及成立条件>

## <下一处实际内容转折>

<继续推进问题，按原片实际给出的判断与限制收束>

<details>
<summary>来源与回看</summary>

原片：<链接或用户提供的文件>。
依据：<字幕或识别来源；真实覆盖范围和存在的疑点>。
回看：<有依据的主题链接；没有时间时省略>。

</details>
```

## 3. 证据与核验

正文使用普通小标题。按 [文字证据与Map-Reduce](summarization.md) 的文章模式保存chapters.json，将各节重要段落与来源对应；时间与item索引无需显示在正文中。没有时间的文稿省略来源秒数。用户要求逐段复盘时，采用该文件的时间轴模式。

**完成标准**：全部文字块已处理，所总结的范围明确；读者能顺着正文理解问题与推理，重要例子、归属、限定和后续修正有据，AI评论另列。原标题匹配，证据核验返回valid=true并完成语义审读，保存summary.md及chapters.json，返回可点击文件路径。
